# MOSS1024×1024: first generation and generation 2 in the same process (2026-10-20 JST)

> Historical test record. See [Turbo4/memory comparisons](moss-turbo-memory-options-20261020.md) and [verification status](status.md) for the currently adopted candidate and latest times.

PS5 FW 12.40 / RADV NAVI21 generated 2 images at 1024×1024,50steps using MOSS-Image-SFT plus the specified LoRA; Windows retrieved PNGs through the OpenAI Images-compatible API. Both images were visually inspected by the root agent. This isolated experiment kept production runtime admission 0.

![1024×1024,50steps generated by MOSS on PS5](images/moss-1024-50step-20261020.png)

## Measured times

| Timing scope | First run (cold) | Run 2 in the same process (warm) |
|---|---:|---:|
| PS5 generation_seconds | **1242.706350 s (20 min 42.7 s)** | **1177.725365 s (19 min 37.7 s)** |
| OpenAI API round trip | 1243.907 s | 1178.875 s |
| Complete Windows verification | 1249.407 s | 1184.609 s |

PS5 generation times differed by 64.981 seconds. The first includes this process's first lazy model load and generation, but the OS disk cache was not flushed; it is not cold-storage timing immediately after reboot. Health confirmed the same model context was loaded for run 2, but CPU text encoding, necessary weight reload/transfer, GPU synchronization, and workspace preparation were not necessarily zero. The difference cannot be treated as pure model-loading time.

## Fixed conditions and evidence

1024×1024,50steps, Euler, CFG 3, flow shift 5, seed 20261020, selected rank 16 LoRA 0.7, Direct pool 10GiB, outside-pool reserve 1GiB, inference budget 9.5GiB. Models: MOSS-Image-SFT Q4_K + Qwen3.5-9B Q4_K_M + FLUX.2 small VAE + external tokenizer. PS5 CPU performs text encoding; Vulkan performs DiT/VAE. VAE uses tile 256/overlap 0.5 across 49 tiles. Windows performs no model inference.

The prompt specified an adult woman with silver-white hair and purple eyes, a red jacket, a neon-city rooftop, meteors, and a night sky. Prompt/negative bytes matched across 2 runs. Both LoRA runs reported loaded/matched/used 504 each, skipped 0, with actual application verified.

Both runs retained the same native/gateway processes. Native SELF SHA 256: `6728ca513b442ec7c30a272f95ba135a217bb154a89e10755722b66dd59d3c3b`. Each phase sent 1 explicit POST with 0 automatic retries. Double terminal-job GETs and native-image GET verified PS5 GPU completion and byte equality with OpenAI-returned PNGs.

## Memory and limitations

| API value (bytes) | First run | Run 2 |
|---|---:|---:|
| peak_cpu_bytes | 11790876672 | 11790876672 |
| peak_gpu_bytes | 4868833280 | 4868833280 |

These include process/owned-pool cumulative high-water marks, not per-image increments. CPU peak RSS and GPU-labeled owned-pool peaks cannot be added. `peak_gpu_bytes` is a peak upper-bound accounting value for shared Direct memory including CPU text weights, not independent dedicated VRAM usage.

The separately authorized 10GiB trial was used; the requested 12GiB + reserve 1GiB remains unmet because native reports 11.4375GiB total. This dedicated benchmark allows at most 2 attempts; failures consume claims and attempt 3 is rejected. The old 256 profile and production admission 0 are unchanged.

Normal shutdown requests to both APIs returned HTTP202; separate observations then confirmed both native/gateway PIDs absent. An independent observer also confirmed no GPU title. Acceptance alone is not termination evidence; separate process and independent-idle checks are retained.

Each condition was observed 1 time. Repeated means/variance, long-running operation, maximum resolution, first run after OS cache flush, minimum necessary steps, other prompts, and 12GiB allocation were outside this measurement.

## Phase timing and metadata boundaries

The cold CPU wall profile recorded DiT graph_total 1189.082695 seconds, graph_call_including_internal_wait 1173.274546 seconds, and weight preparation 13.452070 seconds. DiT graph calls were approximately 94.4% of the cold total. These are CPU wall times including internal waits, not pure GPU timestamps; nested intervals must not be summed. Sampling logs reported 1189.95 seconds, VAE decode 6.66 seconds. Cold log synchronization took Direct pool 0.014855 seconds / startup 0.072663 seconds, with no evidence it occupied most of the 20 minutes.

Preflight synthetic metadata used 1GiB buft blocks and obtained DiT workspace 754MB in 1 chunk. Actual native uses 64MiB suballocation blocks; runtime planning reached 1,185,459,208B across 9 chunks, largest 275,382,272B. The largest tensor was also 275,382,272B, within each 1GiB claim. Actual VAE workspace was 132,251,656B across 3 chunks, with scratch x/y1,572,864B each, unlike synthetic F32 graph scratch 0. Runtime plan/scratch checks confirmed unknown 0 and all claim limits. Synthetic figures are not strict upper bounds for runtime workspace or aggregate physical capacity.

Final cold logs checked 100 DiT outputs, 49 VAE tile outputs, and 62,554,112 values including text, with nonfinite 0 and completed DiT/Flash Attention/VAE witnesses. These are not total GPU operation counts or guarantees across all conditions. Warm phase/cache details require separate actual-log auditing; model_loaded alone does not imply zero weight transfer.
