# 再起動後の小画像試験の範囲

2026-10-19の試験前提を記録します。利用者からの再起動連絡を受けた後も、実際のboot・所有者・サービス復帰は当該実機の読み取りで確認します。過去の受理記録を再利用せず、自動再送・モデル同時起動・大画像・性能測定・連続生成を行いません。この文書の更新はオフライン作業です。

最初に新しいboot世代、旧Anima所有者の不在、BigApp idle、既存サービス・小ファイル読込の復帰を読み取り確認します。PID番号だけで判定せず、古いboot/owner/session/launch/bootstrapの受理記録を再利用しません。前回の生成POST・起動補助スクリプトをそのまま再実行しません。

AnimaはモデルとSELFのローカル整合を確認済みです。動作済みWAIとの確定設定差であるmmapだけをfalseへ変更した候補を用意しています（Anima repoの`config/anima-reboot-smoke.json.example`、元のmmap true設定と実機配置は維持）。Direct量・予備量・FA・精度・CPU数を同時変更しません。停止原因がmmapと確定したわけではありません。初期化の入口・ログ待ちを区別するメモリ工程マーカーも別候補として保存されていますが、停止防止機構ではありません。

復帰後の準備・設定反映と通常起動を確認できた場合だけ、Anima512×512・8steps・CFG1・Eulerを1回送ります。MOSSは準備が整った場合だけ256×256・4stepsを1回送る案です。既存Windows clientの既定は1024なので寸法を必ず明示します。小サイズは品質評価ではなく出力確認です。

**MOSSの通常推論はまだ試験開始不可です。** モデル4個と指定LoRAの全量取得、exact F32化、native設定/qkv接続、全75-member core/nativeのfresh buildは完了しました。PS5への配備、12GiB予約＋CPU等の余裕の実証、Qwen数値とGPU読み戻し、runtime admissionが残っています。過去のDirect報告12GiB/11.4375GiBでは、現12＋予備1GiBの判定を通りません。小画像にしてもこの容量条件は変わりません。ガード解除・目標容量の暗黙引下げや、LoRA未適用を成功扱いすることはしません。

1件が完了し、通常終了とGPU所有者消失を確認してから次へ進みます。タイムアウトはPS5処理停止の証拠ではありません。応答・所有権が曖昧なら再POST、別モデル、新しい診断helperを起動せず、その回の確認を止めます。

本資料に追加したMOSSのhost取得/変換/ビルド検証では、PS5接続・設定変更・再起動・モデル推論は0です。動画撮影は行いません。FW・システム領域・既存WAIを変更しません。初期化で止まった具体的な場所と再発しないことは、現時点では断定できません。
